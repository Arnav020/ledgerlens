# Limitations, Assumptions and Potential False Positives

## Assumptions

- **Synthetic, authorized data.** All demonstration documents are generated by
  `dataset/generate_dataset.py` and contain no real PII. Running on real documents would
  require proper authorization (PS-2 section 13).
- **Packet structure.** The demo expects a loan / KYC packet with files named `01_`..`05_`
  (application, ID, address proof, salary slip, bank statement). The engine generalizes to
  the same document *types*, not to arbitrary unseen layouts.
- **Born-digital statements.** Statement arithmetic and PDF forensics assume a born-digital
  PDF with a text layer. A purely scanned statement would fall back to OCR and would not
  carry PDF-revision evidence.
- **Readable scans.** OCR accuracy depends on image quality; the demonstration images are
  clean and high-resolution.

## Known limitations

- **Visual forensics is unreliable on documents.** Published benchmarks (ICCV 2025 workshop)
  show state-of-the-art image-forgery detectors underperform on documents. LedgerLens
  therefore does not auto-flag from ELA; it uses EXIF metadata (reliable) and shows the ELA
  heatmap only as a human-review aid.
- **Classification and extraction are tuned to the demonstrated document types**, not a
  universal model. New document layouts would need new field anchors or a learned extractor.
- **No signature verification** against a known reference signature.
- **OCR is not treated as ground truth**; field-level confidence is surfaced so a human can
  judge low-confidence reads.

## Potential false positives

- **Address comparison**: minor legitimate formatting differences could, in principle, be
  read as a conflict. The normalizer strips case and punctuation to reduce this, but a
  genuinely reformatted address could still flag and would need human review.
- **PDF incremental updates**: a revision can be entirely benign (for example a legitimate
  e-signature or annotation). This is why the PDF finding is labelled *potential
  manipulation, needs review*, not confirmed.
- **EXIF editing-software tag**: some legitimate scanning or export pipelines write an editor
  signature. Treated as a medium-confidence supporting signal, not proof.
- **OCR misreads**: a misread digit could affect a numeric comparison; field confidence and
  click-to-source let a reviewer verify quickly.

## Design response to these limitations

LedgerLens leads with deterministic, high-confidence checks (cross-document contradictions,
ledger arithmetic, PDF revision structure), reports visual signals only at low/medium
confidence, separates *observed* from *potential*, and keeps a human in the loop for every
consequential decision.
